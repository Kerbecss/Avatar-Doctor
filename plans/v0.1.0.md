## Phase 0 — Planning and workflow bootstrap

### Goal

Adopt the permanent spec-driven workflow and prepare the canonical `v0.1.0` planning contract without product implementation.

### Allowed scope

- Add concise repository rules and canonical planning artifacts.
- Integrate the workflow into contributor documentation.
- Protect the planning paths with deterministic repository validation and focused tests.
- Correct stale factual documentation left after `v0.0.6` completion.
- Open the release Draft Pull Request and obtain repository-validation evidence.

### Required evidence

- The canonical SPEC, this PLAN, and HANDOFF are tracked at policy-defined paths.
- Repository validator and standard-library test suite pass.
- The diff contains no Unity package, dependency, asset, ProjectSettings, or workflow changes.
- The Draft Pull Request reports that implementation has not started.

### Exit gate

Independent external approval of the SPEC and PLAN. Only after approval may the milestone and implementation Issues be created or Phase 1 begin.

### Out of scope

- Avatar Discovery implementation.
- VRChat SDK installation or dependency changes.
- Package version, assembly, source, asset, release, tag, milestone, or Issue changes.

## Phase 1 — VRChat SDK integration boundary

### Goal

Implement the smallest supported compile-time boundary required by `SDK-01`.

### Allowed scope

- Add the SPEC-approved `com.vrchat.avatars` VPM compatibility range.
- Start with the SPEC's intended minimal `VRC.SDK3A` asmdef reference and require external SPEC review before adding any other explicit VRChat SDK assembly reference.
- Add the smallest VRChat-specific source boundary needed to compile against the public descriptor type.
- Add boundary validation or compile fixtures where valuable.

### Required evidence

- Actual package resolution and Unity compilation with an approved stable `3.10.x` SDK prove whether the intended minimal asmdef reference is sufficient.
- Manifest and asmdef diff match the SPEC exactly.
- No reflection, copied SDK code, internal APIs, or unrelated SDK assemblies.
- Repository validation and focused boundary tests pass.

### Exit gate

Independent review confirms the dependency range, assembly boundary, public API use, package integrity, and compilation evidence before discovery work begins.

### Out of scope

- Scene discovery behavior.
- Selection behavior.
- Discovery UI.
- Diagnostics or later roadmap functionality.

## Phase 2 — Scene avatar discovery

### Goal

Implement the candidate model and read-only discovery service required by `DISCOVERY-01` through `DISCOVERY-04`.

### Allowed scope

- Internal candidate and immutable result types.
- VRChat-specific descriptor discovery in valid loaded scenes.
- Inactive roots, multiple scenes, duplicate names, and deterministic ordering.
- Pure ordering tests and focused Unity Editor discovery tests.

### Required evidence

- Tests cover zero, one, multiple, inactive, multi-scene, duplicate-name, unloaded-scene, and deterministic-order scenarios.
- Scene-dirty and mutation assertions remain false.
- Discovery returns only eligible live candidates.
- Repository validation and Unity compilation pass.

### Exit gate

Independent review confirms the discovery algorithm, deterministic key, read-only boundary, SDK isolation, and test evidence before selection work begins.

### Out of scope

- Automatic or manual selection.
- Window state rendering or controls.
- Hierarchy snapshots, inventories, diagnostics, or repairs.

## Phase 3 — Selection model

### Goal

Implement deterministic none/single/multiple selection decisions required by `SELECTION-01` through `SELECTION-04`.

### Allowed scope

- Internal selection state and origin.
- Sole-candidate automatic selection.
- Active Editor selection mapping.
- Manual selection, refresh preservation, and invalidation.
- Nested descriptor and ambiguous-root rules.
- Pure selection tests plus focused integration tests.

### Required evidence

- Tests cover automatic selection, unresolved multiple state, manual preservation, invalidation, outside-avatar selection, nested roots, and ambiguity.
- No valid manual selection is overwritten by automatic input.
- No invalid candidate remains selected.
- Repository validation and Unity compilation pass.

### Exit gate

Independent review confirms selection precedence and edge-case behavior against the SPEC before UI wiring begins.

### Out of scope

- Persistent selection across reloads or restarts.
- Discovery UI layout and lifecycle event wiring.
- Avatar or scene mutation.

## Phase 4 — Editor window discovery UI

### Goal

Connect the existing code-only window to discovery and selection state while satisfying `LIFECYCLE-01` and `UI-01`.

### Allowed scope

- Zero, one, and multiple state presentation.
- Candidate identity, selected-state, and selection-origin presentation.
- Manual selection control and explicit Refresh action.
- Initial discovery and coalesced hierarchy/scene refresh callbacks.
- Editor selection observation and symmetric lifecycle cleanup.
- Focused UI and lifecycle tests where practical.

### Required evidence

- The existing window remains code-only UI Toolkit.
- Repeated events coalesce and no polling or per-frame scan exists.
- Close/reopen and domain reload cannot accumulate callbacks.
- All UI states remain distinguishable with duplicate names.
- Repository validation, tests, and Unity compilation pass.

### Exit gate

Independent review confirms the UI contract, refresh behavior, lifecycle cleanup, and absence of unrelated visual redesign before hardening begins.

### Out of scope

- UXML, USS, presentation assets, or a new design system.
- Diagnostics, repair controls, inventories, or future navigation surfaces.
- Any avatar, scene, or asset mutation.

## Phase 5 — Unity validation and hardening

### Goal

Validate the integrated behavior in Unity and fix only defects that prevent the approved SPEC from being satisfied.

### Allowed scope

- Complete focused Editor tests.
- Run the required manual zero, one, multiple, inactive, multi-scene, duplicate-name, Refresh, close/reopen, and domain-reload scenarios.
- Verify no scene dirtying, mutation, unexpected diagnostics, warnings, or generated files.
- Apply scoped defect fixes and regression tests.

### Required evidence

- All automated repository and feature tests pass.
- The manual Unity validation matrix is recorded against Unity `2022.3.22f1` and an approved stable `3.10.x` SDK.
- Mutation and lifecycle invariants are explicitly verified.
- Any hardening changes trace to a failed SPEC criterion or invariant.

### Exit gate

Independent review confirms every acceptance criterion has evidence and no blocking regression remains before release preparation.

### Out of scope

- New product behavior or architecture.
- GitHub Unity-license CI without separate approval.
- Later-roadmap features or opportunistic refactors.

## Phase 6 — Release preparation and completion

### Goal

Prepare, review, publish, and verify `v0.1.0` using the established release pipeline after implementation approval.

### Allowed scope

- Set package and package-identity version references to `0.1.0`.
- Update changelog and relevant release/status documentation.
- Update validation-policy and protected workflow expected versions.
- Complete final Pull Request review and post-merge CI.
- Build and compare reproducible release artifacts.
- Create the authorized tag and GitHub prerelease.
- Build and verify the non-public listing.
- Perform and record a clean installation.

### Required evidence

- The reviewed commit, manifest, constants, changelog, policy, workflows, tag, artifacts, checksums, and prerelease agree on `0.1.0`.
- Pre-merge and post-merge required CI pass.
- Two artifact builds are byte-identical and verification succeeds.
- The published ZIP matches the tagged package tree through the non-public listing.
- Clean installation and required Unity behavior are verified.

### Exit gate

Independent release review confirms reproducible artifacts, prerelease publication, listing verification, clean installation, and accurate public status before the release is declared complete.

### Out of scope

- New Avatar Discovery behavior during release preparation.
- Work assigned to `v0.1.1` or later.
